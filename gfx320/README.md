# GFX320 MVP

Первая реализованная часть `GFX320.DLL` предназначена только для DSS-режима
`#81` (320×256×256). Она содержит ускоренные очистку, заливку прямоугольника,
горизонтальные/вертикальные линии и вывод 16×16 row-major тайлов из физической
страницы через WIN0.

Готовая релизная библиотека хранится в репозитории как
[`GFX320.DLL`](GFX320.DLL). Потребителям следует брать этот файл напрямую;
инструменты сборки нужны только разработчикам библиотеки.

Сборка:

```sh
make -C gfx320 all
make -C gfx320 verify
make -C gfx320 release BUILD_DATE=YYYY-MM-DD
```

Требуются `sjasmplus`, CLI `sprinter-mkdll` из libman и исходник
`libman13.asm`. По умолчанию Makefile использует соседнее дерево Sprinter:
`../../libman/.venv/bin/sprinter-mkdll` и
`../../../sprinter-rtl8019a/src/lib`. Для другой раскладки пути задаются явно:

```sh
make -C gfx320 all \
  LIBMAN_MKDLL=/path/to/sprinter-mkdll \
  LIBMAN_DIR=/path/to/libman/source
```

Дата DLL берётся из текущей даты; для воспроизводимой сборки передайте
`BUILD_DATE=YYYY-MM-DD`.
Цель `release` сначала проверяет контейнер, затем обновляет отслеживаемый
`gfx320/GFX320.DLL`. Его необходимо коммитить вместе с соответствующими
изменениями исходников.

Для тестирования используйте `gfx320/GFX320.DLL` и
`gfx320/build/GFX320.EXE`. Скопируйте их рядом на Sprinter и запустите EXE.
Пример переключает режим `#81`, создаёт
страницу тайлов через `DSS.GETMEM` + `BIOS.GetMemBlkPages`, рисует фон, панель,
линии, ряд через `gfx_draw_tile_span` и отдельные позиции через
`gfx_draw_tile_list`. Экран остаётся открыт до нажатия клавиши.

Пример строит полный путь `каталог EXE\GFX320.DLL` через `APPINFO`, при
необходимости пробует имя из текущего каталога и загружает DLL в WIN3.
Автоматический `gfx_init`, вызываемый самим `l_load`, не обращается к DSS:
режим `#81` обязан включить клиент до первого рисующего вызова.

`gfx320.inc` содержит номера MVP entry, коды ошибок, флаги, capabilities и
смещения MVP-descriptor. Полный ABI и последующие этапы находятся в
[specs.md](specs.md).

После `LIBMAN.l_call` сначала проверяется `CF` самого libman, затем `A`: `A=0`
означает успех, `A=GFX_ERR_*` — ошибку GFX320. Для entry `>=1` carry,
возвращённый внутренним DLL-entry, не является частью ABI и libman его не
передаёт.

Важно: при каждой операции тайла библиотека на короткое время отключает
maskable interrupts и подключает исходную страницу именно в WIN0. В этот
интервал нельзя вызывать BIOS/DSS/RST; NMI также должен быть отключён согласно
контракту в ТЗ. Для tile entry DLL и текущий стек должны быть расположены вне
WIN0 (пример загружает DLL в WIN3, а код и стек EXE находятся в WIN2).

# WIN320.DLL — руководство разработчика

English version of this document: [GUIDE.md](GUIDE.md).

`WIN320.DLL` — библиотека простого оконного интерфейса для Sprinter в
режиме DSS `#81` (320×256, 256 цветов). Это не фреймворк: библиотека даёт
набор готовых блоков — панели, кнопки, поля ввода, списки, скроллбары,
прогрессбары, иконки, чекбоксы и радиокнопки, — из которых приложение на
ассемблере, C (SDCC) или Turbo Pascal собирает интерфейс в стиле
GFX Viewer / Flex Navigator. Внутри используется аппаратный акселератор
Sprinter, но это деталь реализации, а не часть ABI.

Два равноправных способа работы:

- **декларативный** — контролы описываются packed-структурами, ссылки
  собираются в массив `WinItem[]`, массив — в `WinWindow`; окно рисуется
  одним `win_draw`, обновляется точечно через dirty-флаги и `win_update`;
- **императивный** — те же дескрипторы передаются напрямую в
  `win_button`, `win_panel`, `win_label` и т. д., без окна и массивов.

Дескрипторы в обоих путях одинаковы: структура из списка окна без
изменений работает в прямом вызове.

## 2. Возможности (ABI 2.0)

- **Примитивы** — заливка, 3D-рамка raised/sunken, панель, разделитель,
  XOR-инверсия, пунктирный индикатор фокуса.
- **Текст** — пропорциональный 8-пиксельный шрифт (CP866, вшит в DLL,
  заменяется файлом `WF32` через `win_load_font` без пересборки);
  лейбл с выравниванием, заливкой поля и обрезкой хвоста «..».
- **Контролы** — кнопка (normal/pressed/disabled/focused, глифы
  псевдографики), поле ввода с модальным редактированием, listbox
  (обычные указатели или paged-строки в EMM-страницах), скроллбар со
  стрелками, прогрессбар (проценты), иконки 8×8/16×16 из EMM-страниц с
  аппаратной прозрачностью `#FF`, чекбокс и радиокнопка с группами.
- **Окна** — декларативный список объектов, перерисовка только изменённых
  (`WIN_IT_DIRTY` + `win_update`), LIFO-стек модальных окон с сохранением
  и восстановлением фона (backstore в EMM-страницах приложения).
  Заголовок и кнопка закрытия — опциональные свойства самого окна
  (`WinWindow.title`, `WIN_WND_CLOSE`), а не декларативные объекты:
  `win_draw`/`win_open` рисуют полосу, а трекер отдаёт `WIN_EV_CLOSE` по
  полному нажатию-отпусканию на кнопке закрытия.
- **События** — неблокирующий `win_poll` и блокирующий `win_track`:
  клики, автоповтор, hover/leave, горячие клавиши, сырые коды любой
  клавиши, подобласти скроллбара, строки listbox и кнопка закрытия окна.
- **Фокус клавиатуры** — Tab/Shift+Tab, активация кнопки Enter,
  чекбокса/радио Space, стрелки в радиогруппе; индикатор рисует
  библиотека.
- **Тема** — 18 цветовых ролей одним вызовом `win_set_theme`, включая фон
  и текст заголовка окна; `#FF` в любом цветовом поле дескриптора
  означает «взять из темы».
- **Строки** — глобальный формат ASCIIZ (C/asm) или байт длины
  (Turbo Pascal `string`).
- **Экраны** — вывод в экран 0 или 1 (`win_set_screen`); переключение
  видимого экрана остаётся за приложением.

Сознательно вне целей: перекрывающиеся немодальные окна, z-order,
клиппинг, перетаскивание окон, собственный драйвер мыши.

## 3. Быстрый старт (ассемблер)

Библиотека загружается загрузчиком libman
(`sources/libman/libman/libman.asm`); DLL рекомендуется класть в **WIN3**,
код, данные и стек приложения — в WIN0..WIN2. Loader сам ищет DLL рядом с
EXE:

```asm
        include "win320.inc"

        ld  bc,#0050            ; DSS SETVMOD
        ld  a,#81               ; режим 320x256x256
        rst #10

        ld  hl,dll_name         ; "WIN320.DLL",0
        ld  a,3                 ; окно для DLL (WIN3)
        call LIBMAN.l_load
        jp  c,load_error        ; причина в LIBMAN.l_reason / l_dss_error
        ld  (dll_handle),hl     ; шрифт уже загружен win_init из хвоста DLL

        ld  e,WIN_STYLE_PALETTE|WIN_STYLE_CLEAR
        ld  d,#FF               ; 0..15, либо #FF = цвет рабочего стола темы
        ld  b,WIN_STYLE         ; номер entry из win320.inc
        call api
        jr  nz,win_error        ; A: 0 = успех, #20..#28 = WIN_ERR_*
        ...
api:    ld  hl,(dll_handle)
        call LIBMAN.l_call      ; аргументы: A, DE, IX, IY
        ret c                   ; CF = ошибка диспетчера libman
        or  a                   ; ZF по статусу WIN320
        ret
```

Полный сценарий — [examples/dialog.asm](examples/dialog.asm).

## 4. Соглашение о вызове

- До entry доходят только регистры `A`, `DE`, `IX`, `IY`; `HL`/`BC`
  заняты диспетчером `l_call`. Крупные аргументы передаются
  packed-дескриптором, указатель — в `DE` (смещения полей — в
  `win320.inc`).
- Статус возвращается в `A`: `0` — успех, `#20..#28` — код `WIN_ERR_*`.
  Флаг `CF` принадлежит диспетчеру libman и для entry `>=1` не является
  частью ABI библиотеки.
- Entry 0/1 (`win_init`/`win_free`) вызывает только менеджер при
  `l_load`/`l_free`; приложение их не вызывает.
- Все функции сохраняют регистры, не объявленные входом или результатом.
- Библиотека нереентерабельна: нельзя вызывать её из ISR/NMI и повторно
  до завершения предыдущей операции.

### Размещение данных

На время `l_call` страница DLL подключена в её окно и вытесняет оттуда
страницу приложения, поэтому **никакие данные вызова не могут находиться
в окне DLL**. Дескриптор верхнего уровня копируется в scratch до
подключения VRAM; всё, что читается по ходу работы (строки, `WinItem[]`,
массивы listbox, таблицы клавиш, буфер редактирования), обязано быть
доступно весь вызов. Часть структур библиотека изменяет (`WinWindow.focus`,
`WinItem.flags`, флаги и internal-поля контролов, выходные поля
`WinTrack`, буфер edit) — они должны лежать в записываемой RAM; в C их
нельзя объявлять `const`.

### Коды ошибок

| Код | Имя | Значение |
|---:|---|---|
| `#20` | `WIN_ERR_ARGUMENT` | некорректный параметр/структура |
| `#21` | `WIN_ERR_VIDEO_MODE` | активен не режим `#81` |
| `#22` | `WIN_ERR_WINDOW` | конфликт CPU-окна (DLL/`SP`/рабочие окна) |
| `#23` | `WIN_ERR_BACKSTORE` | backstore не задан или не хватает места |
| `#24` | `WIN_ERR_DEPTH` | переполнение/исчерпание стека окон |
| `#25` | `WIN_ERR_UNSUPPORTED` | функция/флаг не поддерживается |
| `#26` | `WIN_ERR_BUSY` | конфликт незавершённой операции |
| `#27` | `WIN_ERR_FONT` | шрифт не загружен / ошибка файла шрифта |
| `#28` | `WIN_ERR_MEMORY` | не удалось выделить EMM-память |

## 6. Координаты, геометрия, начало отсчёта

Каждый рисуемый дескриптор начинается одинаковым 8-байтным заголовком:
`x`, `y`, `width`, `height` — все `u16` little-endian (`y` 0..255,
`y+height` ≤ 256, `x+width` ≤ 320). Благодаря общему заголовку hit-test
читает первые восемь байт любого контрола, не зная его типа, а геометрия
объекта хранится ровно в одном месте.

Координаты дескрипторов относительны **началу отсчёта** (по умолчанию
`0,0` — то есть экранные). Исключение — `WinWindow`: его `x,y` абсолютны,
окно само задаёт начало отсчёта. `win_draw`/`win_update`/`win_poll`
устанавливают его из окна на время вызова; `win_open` — до
соответствующего `win_close`; `win_set_origin` задаёт его явно для
императивного рисования. Следствие: диалог перемещается правкой двух
полей `WinWindow.x/y` без пересчёта координат объектов.

Нулевые `width`/`height` — успешная пустая операция; выход за экран —
`WIN_ERR_ARGUMENT` без записи.

## 7. Цвет и тема

Два разных понятия:

- **`color`** — один индекс `0..15`; используется геометрическими
  примитивами (заливка, тело панели);
- **`attr`** — байт `d7..d4` фон, `d3..d0` текст; используется только
  текстом.

Значение `#FF` в любом поле `color`/`attr` означает «взять из темы» — это
значение по умолчанию, поэтому типичный интерфейс не содержит явных
цветов и перекрашивается одним `win_set_theme`. Индексы отображаются в
верхние 16 позиций палитры (`#F0|color`); нижние 240 остаются приложению.

`WinTheme` — 18 однобайтных ролей:

| Роль | По умолчанию | Назначение |
|---|---:|---|
| `WIN_TH_LIGHT` / `WIN_TH_SHADOW` | 15 / 7 | свет и тень 3D-бевеля |
| `WIN_TH_FACE` | 8 | тело панелей, кнопок, окон |
| `WIN_TH_DESKTOP` | 1 | фон рабочего стола |
| `WIN_TH_TEXT` / `WIN_TH_TEXT_DISABLED` | 0 / 7 | текст / текст disabled |
| `WIN_TH_FIELD_BG` / `WIN_TH_FIELD_FG` | 15 / 0 | поле ввода и список |
| `WIN_TH_CURSOR_BG` / `WIN_TH_CURSOR_FG` | 1 / 15 | выделенная строка |
| `WIN_TH_PROGRESS` / `WIN_TH_PROGRESS_FILL` | 7 / 1 | прогрессбар |
| `WIN_TH_SCROLL_TRACK` / `WIN_TH_SCROLL_THUMB` | 7 / 8 | скроллбар |
| `WIN_TH_FOCUS_MASK` | `#0F` | XOR-маска пунктира фокуса |
| `WIN_TH_TITLE_BG` / `WIN_TH_TITLE_FG` | 1 / 15 | заголовок окна |

`win_style` — сервис инициализации экрана: загрузка стандартной
EGA-палитры в `#F0..#FF` (`WIN_STYLE_PALETTE`), заливка экрана
(`WIN_STYLE_CLEAR`), применение к обоим экранам (`WIN_STYLE_BOTH`).

## 8. Декларативное окно

`WinWindow` (20 байт): геометрия, `color`, флаги (`WIN_WND_NOPANEL` — не
рисовать тело, `WIN_WND_SUNKEN`, `WIN_WND_CLOSE` — рисовать кнопку
закрытия в заголовке), `count`, `focus` (индекс записи с фокусом, `#FF`
— нет), указатель `items`, `title` (указатель на строку, 0 — без
заголовка), `title_attr`, служебный `last_focus`.

### Заголовок окна и кнопка закрытия (ABI 2.0)

Если задан `title`, рисуется тематическая полоса вдоль верхней границы
окна с обрезаемым по `".."` лейблом внутри неё; `WIN_WND_CLOSE`
дополнительно рисует глиф закрытия и делает его кликабельным. Оба — это
свойства окна, а не декларативные объекты: дополнительные записи
`WinItem` не нужны. При `title=0` флаг `WIN_WND_CLOSE` обязан быть
сброшен; при ненулевом `title` обязаны выполняться `WIN_WND_NOPANEL`
сброшен, `width>=20`, `height>=18`. Нарушение любого условия возвращает
`WIN_ERR_ARGUMENT` из `win_draw`/`win_open` **до** какой-либо записи в
экран. Полное нажатие-и-отпускание на кнопке закрытия отдаёт
`WIN_EV_CLOSE` (`id`/`index` — `#FF`); отпускание снаружи отменяет
действие, а клик по остальной части полосы поглощается без события.

`WinItem` (8 байт на запись, без терминатора — длину задаёт `count`):

```text
type      WIN_T_*: label, fill, frame, panel, separator, button, icon,
          progress, scrollbar, listbox, edit, zone, checkbox, radiobutton
flags     WIN_IT_*
id        идентификатор в событиях (#FF зарезервирован)
control   указатель на дескриптор контрола
user_data возвращается в событии
```

Флаги записи:

| Флаг | Смысл |
|---|---|
| `WIN_IT_DIRTY` | перерисовать при `win_update`; библиотека снимает |
| `WIN_IT_HIDDEN` | не рисовать и не тестировать |
| `WIN_IT_DISABLED` | рисовать выключенным, исключить из ввода и Tab |
| `WIN_IT_HIT` | участвует в hit-test мыши (положительный флаг!) |
| `WIN_IT_FOCUSABLE` | участвует в Tab-обходе |
| `WIN_IT_PRESS` | анимировать нажатие |
| `WIN_IT_REPEAT` | автоповтор при удержании LMB |
| `WIN_IT_HOVER` | события `WIN_EV_HOVER`/`WIN_EV_LEAVE` |

Интерактивным объектам `WIN_IT_HIT` ставится явно; декоративный лейбл
становится кликабельным тем же флагом. `WIN_T_ZONE` — невидимая зона
(геометрия из `WinRect`) для областей, которые приложение рисует само.

Отрисовка:

- `win_draw` — полный рендер: тело окна, объекты по возрастанию индекса,
  синхронизация индикаторов фокуса, снятие всех dirty-флагов;
- `win_draw_item` — полный рендер одного объекта за `O(1)`;
- `win_update` — дифференциальный проход: перерисовывает только записи с
  `WIN_IT_DIRTY` (контролы с internal-полями `last_*` рисуют лишь
  разницу), снимает флаги, возвращает счётчик.

Типовой цикл: обработать событие → изменить состояние контрола → ставить
`WIN_IT_DIRTY` → `win_update`.

### Модальные окна (backstore)

Приложение выделяет 1..4 EMM-страницы (`DSS GETMEM #3D` →
`BIOS EMM_FN5 #C5`) и передаёт их `win_set_backstore`. `win_open` всегда
сохраняет фон под окном, рисует его и запоминает начало отсчёта;
`win_close` восстанавливает фон строго LIFO (глубина до 4). Сохранение
привязано к экрану: `win_set_screen` между open и close не собьёт
восстановление. При ошибке в списке объектов `win_open` атомарно
откатывается — частично нарисованный диалог на экране не остаётся.
Страницы освобождает приложение после `l_free`.

## 9. События: `win_poll` и `win_track`

Дескриптор `WinTrack` (32 байта) принадлежит приложению и содержит:
указатель на `WinWindow` (объекты + начало отсчёта; 0 — только
клавиатура), таблицу горячих клавиш `WinKey[]`, опции, выходные поля
события и 8 байт внутреннего состояния трекинга (обнулить перед первым
вызовом). Состояние живёт у вызывающего: два диалога с двумя `WinTrack`
полностью независимы.

- `win_poll` — одна неблокирующая итерация; нет события —
  `WIN_EV_NONE`. Для приложений с фоновой работой.
- `win_track` — блокирует до события; с `WIN_TRK_HALT` выполняет `HALT`
  между итерациями.

Опции: `WIN_TRK_ANY_KEY` (возвращать любую клавишу), `WIN_TRK_OUTSIDE`
(клик мимо всех объектов), `WIN_TRK_HALT`, `WIN_TRK_SHOW_CUR`,
`WIN_TRK_TAB_FOCUS`.

События:

| Код | Имя | Когда |
|---:|---|---|
| 0 | `WIN_EV_NONE` | только `win_poll`: событий нет |
| 1 | `WIN_EV_LCLICK` | клик (press+release внутри объекта); для `WIN_IT_REPEAT` — сразу при нажатии |
| 2 | `WIN_EV_RCLICK` | правая кнопка над объектом |
| 3 | `WIN_EV_REPEAT` | тик автоповтора (темп: `repeat_delay`/`repeat_rate` в итерациях) |
| 4 | `WIN_EV_HOTKEY` | совпадение с записью `WinKey` |
| 5 | `WIN_EV_KEY` | любая клавиша при `WIN_TRK_ANY_KEY`; сырые ASCII/скан-код/модификаторы |
| 6 | `WIN_EV_HOVER` | курсор вошёл в объект с `WIN_IT_HOVER` |
| 7 | `WIN_EV_LEAVE` | курсор покинул такой объект |
| 8 | `WIN_EV_OUTSIDE` | клик вне всех hit-объектов (`id=#FF`) |
| 9 | `WIN_EV_FOCUS` | фокус перемещён Tab/Shift+Tab |
| 10 | `WIN_EV_CHANGE` | библиотека изменила checkbox/radio (перерисовка уже выполнена) |
| 11 | `WIN_EV_CLOSE` | кнопка закрытия окна нажата и отпущена (`id=#FF`) |

Дополнительный контекст события — в полях `WinTrack`: `index` записи,
`part` (подобласть: стрелки/страницы/ползунок скроллбара, строка
listbox), `item` (индекс строки listbox), координаты и кнопки мыши,
`user_data`.

Зоны полуоткрытые (`x <= mx < x+width`); hit-test идёт по убыванию
индекса — объект, нарисованный последним, получает событие первым.

### Мышь и курсор

Драйвер мыши инициализирует **приложение** (BIOS `RST #30`, `C=0`) до
первого опроса; библиотека вызывает только READ/SHOW/HIDE/LOAD CURSOR.
`WIN_TRK_SHOW_CUR` в `win_track` показывает курсор на входе в блокирующий
цикл и прячет перед возвратом; клиент `win_poll` управляет постоянной
видимостью сам, а флаг лишь разрешает библиотеке парный HIDE/SHOW вокруг
её перерисовок. `win_set_cursor` переключает стрелку/«ожидание» или
загружает пользовательский спрайт (до 32×32, формат BIOS).

### Фокус клавиатуры

Источник истины — `WinWindow.focus`. Tab/Shift+Tab (при
`WIN_TRK_TAB_FOCUS`) циклически обходят записи с `WIN_IT_FOCUSABLE`;
индикатор (пунктир на кнопке и подписи checkbox/radio, курсорная строка
listbox, текстовый курсор edit) рисует библиотека. Enter активирует
сфокусированную кнопку, Space — checkbox/radio, стрелки перемещают выбор
внутри радиогруппы. Программная смена фокуса: записать `focus` и вызвать
`win_update`. Клик мышью по объекту с `WIN_IT_FOCUSABLE` тоже переводит
фокус.

## 10. Контролы

### Поле ввода (`WinEdit`, 16 байт)

Буфер — источник истины (`len` библиотека вычисляет сама); формат ASCIIZ
или Pascal-строка по `win_set_text_format`, поэтому буфер напрямую
совместим со `string[maxlen]` TPC. `win_edit_draw` рисует поле (курсор
виден только при `WIN_ED_FOCUS`); `win_edit` — модальное редактирование:
печатные символы, Backspace/Delete, Left/Right, Home/End,
Ctrl+Left/Right по словам, мигающий каретный курсор, откат по Esc, клик
внутри поля позиционирует курсор. Выход: `WIN_ED_ENTER`, `WIN_ED_ESC`,
`WIN_ED_TAB` (при переданном `WinTrack` фокус уже переведён),
`WIN_ED_MOUSE` (событие мыши заполнено в `WinTrack`). `WIN_ED_PASSWORD`
выводит `*`.

### Listbox (`WinListbox`, 28 байт)

Два режима хранения строк: обычный массив `u16`-указателей (лучший для
небольших списков в памяти приложения) или `WIN_LB_PAGED` — таблица
3-байтных `WinTextRef` (`page`,`offset`) в EMM-странице, строки — в любых
EMM-страницах (до 5461 записи). Число видимых строк выводится из
`height/item_height`; при `WIN_LB_FRAME` содержимое имеет отступ 2 px.
Отрисовка дифференциальная: движение курсора перерисовывает две строки,
сдвиг `first` на строку выполняется акселераторным скроллом содержимого.
Связанный `scrollbar` только синхронизируется полями — сам скроллбар
объявляется отдельной записью `WIN_T_SCROLLBAR` (рекомендуется сразу
после listbox). Навигация — за приложением: события дают индекс строки,
приложение меняет `first/cursor`, ставит dirty, вызывает `win_update`.

### Скроллбар (`WinScrollbar`, 22 байта)

`init` вызывается один раз (валидация + sentinel полного рендера);
`draw` сам пересчитывает ползунок из `first/visible/total` и
перерисовывает только разницу. `WIN_SB_ARROWS` добавляет концевые кнопки,
обслуживаемые самим контролом; hit-test возвращает подобласть в
`WinTrack.part` (стрелки, страницы, ползунок). Ориентация —
`WIN_SB_HORIZONTAL`.

### Прогрессбар (`WinProgress`, 12 байт)

Единица — процент `0..100` (поле `percent`); масштабирование своего
счётчика выполняет приложение. `init` — один раз; `draw` рисует
инкрементально только полосу между прежней и новой границей.

### Иконки (`WinIcon`, 12 байт)

Ячейки 8×8 (64 байта, 256 слотов/страницу) или 16×16 (256 байт,
64 слота) лежат в EMM-страницах приложения; дескриптор адресует
`page`+`slot`. Пиксели — полные 8-битные индексы палитры; при
`WIN_ICO_KEYED` байт `#FF` прозрачен (аппаратно, через VRAM-алиас `#58`,
зеркало остаётся корректным для backstore). Паковщик
`tools/winiconpack.py` собирает `WIP1`-файл и манифесты для
asm/C/Pascal; загрузчик приложения выделяет страницы, копирует payload и
подставляет физические номера страниц в дескрипторы.

### Checkbox и radio button (`WinChoice`, 14 байт)

Общая структура: геометрия (минимум 13×10), `attr`, флаги
(`WIN_CH_CHECKED`, `WIN_CH_DISABLED`), `group` (0 у чекбокса; у радио —
номер группы в пределах одного окна), текст подписи. Клик и Space
переключают состояние; радио снимает отметку с остальных элементов
группы; стрелки двигают выбор по группе; группа — одна Tab-остановка.
После фактического изменения библиотека сама перерисовывает затронутые
записи и возвращает `WIN_EV_CHANGE`. Программное изменение: записать
`WIN_CH_CHECKED`, поставить `WIN_IT_DIRTY`, вызвать `win_update`
(эксклюзивность группы в этом случае — на приложении).

## 11. Примеры

Полные, собираемые примеры одного диалога: панель, лейблы, поле ввода,

- SDCC — [examples/dialog.c](examples/dialog.c);
- Turbo Pascal — [examples/DIALOG.PAS](examples/DIALOG.PAS).

C (обёртки из `bind/win320.h`; `win320_bind(handle)` привязывает их к
загруженной DLL, шим `win320_libman_call` предоставляет приложение):

```c
static win_button_t ok = {40, 154, 72, 20, 0xff, 0, 0}; /* x,y,w,h,attr,flags,text */
static win_item_t items[7];
static win_window_t window = {32, 20, 256, 216, 0xff, 0, 7, 2, 0, 0xff, 0};
static win_track_t track;

win320_bind(handle);
win320_set_text_format(WIN_TXT_ASCIIZ);
win320_draw(&window);
for (;;) {
    if (win320_poll(&track)) break;          /* ошибка ABI */
    if (track.event == WIN_EV_NONE) continue;/* фоновая работа здесь */
    if (track.id == ID_CANCEL) break;
    items[STATUS_INDEX].flags |= WIN_IT_DIRTY;
    win320_update(&window, &drawn);
}
```

## 12. Ограничения и безопасность

- Приложение включает режим `#81` само; библиотека не меняет видеорежим
  и видимый экран.
- Рекомендуемая раскладка: DLL в WIN3, приложение в WIN0..WIN2. Рабочие
  окна для временного mapping VRAM/шрифта/backstore/иконок библиотека
  выбирает автоматически (`WIN_WORK_AUTO`), исключая окно DLL и окно
  текущего `SP`; `win_set_work_windows` задаёт их явно.
- Внутри временного mapping (короткие DI-секции) запрещены NMI; стек и
  DLL не должны находиться в WIN0 при его использовании.
- Не печатайте через консоль DSS при активном `#81`: текстовый экран и
  знакогенератор живут в той же VRAM — вывод портит картинку. Ждите
  клавиши тихо (`DSS #30`) и печатайте после возврата текстового режима.
- Рисование поверх области BIOS-курсора при прямых вызовах — с
  предварительным HIDE (или держите курсор скрытым на время построения
  экрана).

## 13. Сборка и проверка

```sh
make -C win320 all        # DLL, визуальный тест, биндинги
make -C win320 verify     # проверка контейнера L0 (с хвостом шрифта)
make -C win320 host-test  # python-тесты ABI и инструментов
make -C win320 z80-test   # прогон DLL в эмуляторе
make -C win320 bindings   # обёртка SDCC
make -C win320 examples   # сборка примеров
make -C win320 benchmark  # build/WINBENCH.EXE — замеры на железе
make -C win320 release    # verify + тесты + обновление WIN320.DLL/EXE
```

Требуются `sjasmplus`, Python 3, `z88dk-ticks`, SDCC для биндингов и
соседний checkout `sources/libman`. `WIN320.EXE` кладётся рядом с
`WIN320.DLL` и `ICONS.WIP` и прогоняет все экраны контролов на обоих
видеобуферах.
